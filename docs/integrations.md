# Интеграции: GetCourse, Bitrix24, Robokassa

Ключи и пароли хранятся только на сервере в `/etc/gripinsky/env` (права 0600). Образец: `.env.example`. В репозиторий, админку, чат и почту они не попадают. Несекретные настройки (воронка, налоги для чека, группа) задаются в админке: «Сайт → Интеграции».

Режим оформления заказа задаёт `CHECKOUT_MODE` на сервере:
- `demo`: заявка с составом заказа уходит в Bitrix24, оплаты нет (сейчас);
- `getcourse`: заказ создаётся в GetCourse, покупатель переходит на оплату GetCourse;
- `robokassa`: прямая оплата Robokassa с чеком 54-ФЗ.

Если выбранная система недоступна, покупатель не теряется: заявка уходит в Bitrix24, менеджер присылает ссылку на оплату.

## Проверка подключения

```bash
curl -s -u editor https://gripinsky.ru/api/admin/status -H "X-Admin-Token: $ADMIN_STATUS_TOKEN"
curl -s -u editor "https://gripinsky.ru/api/admin/status?check=1" -H "X-Admin-Token: $ADMIN_STATUS_TOKEN"   # + пробный запрос в Bitrix24 (только чтение)
```

Ответ показывает, что настроено (`true`/`false`), режим, тестовый режим Robokassa и состояние базы заказов. Значения ключей не показываются.

## GetCourse

1. В GetCourse: Профиль → Настройки аккаунта → API, сгенерировать секретный ключ. Проверить, что на тарифе есть API.
2. На сервере: `GETCOURSE_ACCOUNT=имя` (из адреса имя.getcourse.ru) и `GETCOURSE_API_KEY=…`. Имя аккаунта можно указать и в админке.
3. В GetCourse создать предложения для каждого курса и формата обучения. Коды предложений вписать в карточки курсов и форматов в админке (поле «Код предложения GetCourse»).
4. `CHECKOUT_MODE=getcourse`, перезапустить сервис: `sudo systemctl restart gripinsky`.
5. Проверка: оформить тестовый заказ на предложение с ценой 1 ₽, убедиться, что пришла ссылка на оплату и заказ виден в GetCourse.

## Bitrix24

1. В Bitrix24: Разработчикам → Другое → Входящий вебхук, права `crm`. Скопировать адрес вида `https://ИМЯ.bitrix24.ru/rest/1/ключ/`.
2. На сервере: `B24_WEBHOOK_URL=…`.
3. В админке «Интеграции → Bitrix24»: лид или сделка (если CRM в режиме без лидов), воронка, стадия, ответственный, источник, шаблон названия.
4. Проверка: `/api/admin/status?check=1` → `bitrix24.check: "ok"`, затем отправить заявку с сайта.

## Robokassa (прямая оплата)

1. В кабинете Robokassa: магазин, алгоритм подписи SHA-256, Result URL `https://gripinsky.ru/api/robokassa/result` методом POST, Success URL `/oplata/uspeh`, Fail URL `/oplata/oshibka`.
2. На сервере: `ROBOKASSA_LOGIN`, `ROBOKASSA_PASS1`, `ROBOKASSA_PASS2`, `ROBOKASSA_HASH=sha256` и обязательно явно `ROBOKASSA_IS_TEST=true` (тест) или `false` (боевой режим). Без явного значения прямая оплата не включится.
3. В админке «Интеграции → Robokassa»: система налогообложения, НДС, признак и предмет расчёта для чека.
4. В `deploy/nginx/gripinsky.conf` раскомментировать список IP Robokassa для Result URL после сверки с документацией.
5. `CHECKOUT_MODE=robokassa`, перезапуск. Тестовый платёж, затем `ROBOKASSA_IS_TEST=false`.

Защита оплаты: подпись уведомления проверяется за постоянное время, сумма сверяется с заказом в базе `orders.db`, повторное уведомление не создаёт второй лид, тестовый платёж в боевом режиме отклоняется.

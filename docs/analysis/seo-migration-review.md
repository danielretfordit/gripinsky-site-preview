# Ревизия органических страниц перед переездом

Дата: 06.10.2026  
Источники: таблица `gripinsky_popular_pages` (143 URL, данные за 6 месяцев), `docs/url-map.md`, экспорт Tilda в `docs/tilda/` и текущие маршруты прототипа.

## Решение по переезду

Сохраняем действующие URL и SEO-поля старых страниц, если тема и предложение остаются актуальными. Низкий органический трафик сам по себе не причина удалять страницу: в таблице нет данных о переходах из соцсетей, закладок и внешних ссылок. Решение об архиве принимаем только после проверки продукта и всех источников трафика.

В архиве Tilda есть Title и Description для 90 страниц (`docs/tilda/pages.json`) и текстовый экспорт страниц (`docs/tilda/pages/`). Этот снимок не менять. На прототип уже перенесены метаданные для 67 адресов, которые сохраняются с тем же URL: Title и непустые Description совпадают с архивом дословно. У 31 страницы старое Description было пустым — сохранено подготовленное фактическое описание прототипа. Остальные 23 адреса пока не представлены в прототипе под исходным путём; их метаданные не назначались другим страницам автоматически. Любые новые изменения метаданных выносим на отдельный этап после переезда и фиксации исходных показателей.

## Как сохранить старые SEO-поля

1. Не менять архив `docs/tilda/pages.json`: он хранит исходные Title и Description 90 страниц.
2. Сформировать перед запуском реестр `старый URL → новый URL → старый Title → старый Description → новый Title/Description → решение → HTTP-код`. Использовать его как контрольную точку перед DNS-переключением.
3. Если URL и тема не меняются, на первом запуске сохранить старые Title и Description дословно. Если старое поле пустое, использовать подготовленное фактическое описание и отметить это в реестре.
4. Если URL объединяется, старые метаданные не переносятся все вместе на одну страницу. Зафиксировать исходные значения, выбрать одну целевую страницу и после переезда проверять запросы и посадочные страницы в Яндекс Вебмастере и Google Search Console. Новую оптимизацию метатегов проводить отдельным этапом.
5. Не удалять контент со старого сайта и не включать переадресации до публикации и проверки соответствующей новой страницы и целевого 301.

## Новая админка Keystatic

Визуально проверены список коллекций и карточка курса `/modeling1` в локальной админке.

- В карточке курса доступны редактируемые `SEO → Title` и `SEO → Description`; подсказки указывают длину Title 50–70 знаков, Description 140–160 знаков и подстановку `{price}`.
- У профессии доступны SEO Title, Description и H1.
- У статьи блога доступны заголовок, короткое описание для поиска и соцсетей и старый URL.
- Для главной, каталога, категорий `/courses-page/*`, блога как раздела, галереи и институциональных страниц SEO-поля зашиты в Astro-компонентах, в админке их нет.
- В админке нет реестра старых метаданных, canonical/noindex для каждого URL и списка 301. Редиректы сейчас в конфигурации сайта и должны быть дополнены конфигурацией хостинга.

Решение: добавлена коллекция «SEO страниц» в Keystatic. Для статических страниц и категорий каталога в неё перенесены архивные значения для совпадающих URL; редактор может менять путь, Title, Description, canonical, noindex и изображение для соцсетей. Страницы курсов, профессий и статей продолжают использовать SEO-поля своих записей. Архивные Title и Description курса теперь выводятся без автоматической замены регистра или обрезки; шаблон `{price}` подставляет актуальную цену там, где он задан. Канонический адрес по умолчанию строится из URL страницы, noindex-страницы исключаются из sitemap.
